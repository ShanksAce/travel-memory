# 8 分鐘展示流程
展示前：確認網路可用，登入網站，按「載入示範旅行」。示範是虛構內容，不是使用者真實旅遊紀錄。準備 tests/fixtures/tokyo-exif.jpg 作為帶 EXIF 的測試照片，再準備一張自己的無 GPS 照片對照。

| 時間 | 畫面／操作 | 說明重點 |
|---|---|---|
| 0:00–0:40 | 首頁 | 動機：整合旅行前期待、旅途中紀錄與旅行後回憶 |
| 0:40–1:30 | 世界地圖、台南足跡 | 地圖與旅行互相連結；統計依已到訪紀錄計算 |
| 1:30–2:20 | 建立未來旅行 | 日期驗證、旅行狀態、首頁出發倒數 |
| 2:20–3:20 | 東京旅行／行程規劃 | 新增景點、交通或住宿，預算加總 |
| 3:20–3:50 | 出發準備 | 勾選準備項目，完成率即時變化 |
| 3:50–5:00 | 上傳測試照片 | EXIF 拍攝日期／GPS → 東京；切換依日期及城市分類 |

| 6:15–7:10 | 架構與 ER 圖 | 前端、API、D1、R2、登入權限的責任 |
| 7:10–8:00 | 測試與限制 | 測試結果、GPS 缺失策略、未來研究方向 |

不要把示範 JPEG 的單色畫面當成辨識景點的證據；它用來驗證 metadata 解析。EXIF 日期可以不在旅行日期內，相簿仍保留原始日期，由使用者修正。

## 簡報內容（10 頁）
1. 題目：Travel Memory／互動式旅遊規劃與足跡紀錄系統。姓名與學號由組員填寫。
2. 動機：資訊分散；期待下一次旅行；記錄位置與心情。
3. 使用流程：建立旅行 → 規劃 → 倒數 → 打卡／照片／日記 → 回顧。
4. 功能展示：世界地圖、旅行、相簿、日記。
5. 技術架構：React → Workers API → D1／R2，平台登入。
6. 資料庫：Trip 作為中心，五種子紀錄，外鍵與索引。
7. 照片分類：EXIF → GPS → Haversine → 50 公里鄰近城市 → 人工確認。
8. 測試：8 項 domain、23 項 API、2 項 EXIF；明確註明本機環境。
9. 限制：城市覆盖、HEIC、全量載入、未做正式使用者研究。
10. 結論與後續：核心流程整合完成；進行使用者測試、標準化及效能優化。
